Where sites fail

For each indicator, the five checks that fully scanned sites fail most often. A site can fail more than one check, and each check links to its standard and how to fix it.

Accessibility

Meet WCAG standards so every type of user can use your website. The most common accessibility failure is Links have a discernible name: 41% (1,679 of 4,105 sites) fail it.

What each accessibility check means
  • Links have a discernible name. Links have unique, descriptive text so users know where they go. Screen reader users cannot identify or interact with elements.
  • Heading elements appear in a sequentially-descending order. Page headings follow a logical order without skipping levels. Keyboard users cannot efficiently navigate your site.
  • Background and foreground colors have a sufficient contrast ratio. Text and background colors meet minimum contrast ratios. Users with low vision cannot read your text.
  • Touch targets have sufficient size and spacing. Buttons and interactive elements are large enough to tap easily on touch screens. Users with motor disabilities struggle to tap small buttons.
  • Document has a main landmark. The page has exactly one main content area so screen readers can navigate to it. Screen reader users cannot skip directly to main content.

Botability

Help AI and search engines discover, crawl, and index your website. The most common botability failure is GovernmentOrganization Schema.org type: 81% (3,342 of 4,105 sites) fail it.

What each botability check means
  • GovernmentOrganization Schema.org type. Homepage is marked up as an official government organization. Systems cannot verify you are an official government site.
  • Link text. Links use descriptive text that tells users and search engines where they go. Users cannot tell where links go.
  • Sitemap status. The sitemap file loads and returns a successful response. Search engines cannot find all your pages.
  • Sitemap XML. The sitemap file uses the required XML format. Search engines cannot read your sitemap.
  • Sitemap in robots.txt. The robots.txt file links to the sitemap. Search engines take longer to find your pages.
Botability: Standards · Guidance · Project ScanGov rankings · How ScanGov helps

Security

Secure your site and protect users with proper security practices. The most common security failure is Errors in the console: 40% (1,633 of 4,105 sites) fail it.

What each security check means
  • Errors in the console. The page loads without JavaScript or network errors. Site may have hidden bugs that break features.
  • Sponsored top-level domain (sTLD). The site uses a government-issued domain (.gov, .edu, or .mil). People cannot tell if your site is real government.
  • Security.txt. The site has a security.txt file so researchers know how to report issues. Security researchers cannot report problems to you.
  • X-Content-Type-Options. The site tells browsers not to guess the type of files it serves. Browsers might run dangerous files by mistake.
  • Hypertext Transfer Protocol Secure (HTTPS). The site uses HTTPS to encrypt data between the server and users. Hackers can see and steal personal information.
Security: Standards · Guidance · Project ScanGov rankings · How ScanGov helps

Usability

Optimize content structure so users quickly find what they need. The most common usability failure is Open Graph image alt: 94% (3,857 of 4,105 sites) fail it.

What each usability check means
  • Open Graph image alt. The social media preview image has alt text for screen readers. Screen readers cannot describe shared images.
  • Open Graph site name. The site has a name for social media and browser display. Site name missing in social media shares.
  • Largest Contentful Paint (LCP). The page's main content loads within 2.5 seconds. Users wait too long and leave your page.
  • Open Graph description. The page has a description for social media previews. Shared links have no description on social media.
  • Open Graph type. The page declares its content type for social media cards. Social media shows wrong content type.

About this data

ScanGov scans the homepage of every government site on our list. Scores come from the checks listed on standards.scangov.org. Sites were scanned between 7/18/2026 and 9/19/2026; each site's report shows its own scan date. A site counts as fully scanned when its homepage returned successfully and sent the scanner its page content. Averages, grade shares, failure rates, and ranks use fully scanned sites only. We weren't able to fully scan 646 sites because they did not respond, blocked the scanner, or returned no page content. They appear in the table without grades, each with its scan status, and are left out of every figure. Grades follow the ScanGov grade scale, and rank follows the ScanGov ranking method. The full dataset, including every county's raw results, is published in the ScanGov data repository.
